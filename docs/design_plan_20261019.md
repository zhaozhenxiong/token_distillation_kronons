# CZSC 量价知识蒸馏到 Kronos 实施计划

> 历史方案。真实训练已经接通，当前操作以[蒸馏指南](distillation_guide.md)为准。

日期：2026-10-19。阶段：方案完成，尚未实施训练。目标是把 CZSC 及现有量价引擎的可学习知识写入 Kronos 学生参数，使日常预测和评分只依赖行情、日期与一个学生模型包。

推荐路线：**冻结 tokenizer，以现有 Kronos-base 为起点，通过 LoRA 和多任务监督学习因果量价特征、已确认事件及未来预测；验收后合并权重，部署一个包含内部输出头的学生模型。** CZSC 只在离线准备训练监督和评估基准时运行。这里的教师主要是规则引擎，因此首版属于规则教师监督与多任务蒸馏，不必先训练另一个大型教师网络。

## 1 目标和当前基础

期望的两条链路：

```text
离线训练
历史 OHLCVA ──截至预测原点截断──┬─ CZSC/量价教师 → 特征、事件、有效掩码
                            └─ tokenizer → Kronos 学生 → 联合训练
已成熟的真实后续行情 ────────────→ 未来 token 和方向标签

日常推理
截至当日的 OHLCVA + 已知日期 → 固定 tokenizer → 蒸馏学生模型
                                              ├─ 方向与风险估计
                                              ├─ 量价状态与事件估计
                                              └─ 可选的未来 K 线路径
```

“一个模型”指一个学生预测模型及其内部小头；tokenizer、输入核验、校准参数和账户执行规则仍是必要运行组件。线上预测与评分不再依赖 CZSC、量价特征引擎或外部 MLP。学生输出的结构和事件是估计，不能显示为原生 CZSC 已确认事实；需要精确笔、中枢或原生结构图时，另行调用原有分析入口。

当前代码已具备以下基础，仍需新增权重训练：

| 部分 | 已有事实 | 本计划需要的变化 |
| --- | --- | --- |
| Kronos | `services/kronos_prediction.py` 冻结参数并使用推理模式；`kronos_tuning.py` 只比较 lookback、温度、top_p、采样数 | 独立训练适配器、真实梯度更新、检查点与训练恢复 |
| 模型接口 | `vendor/kronos/kronos.py` 有双 token forward；`decode_s1` 返回隐层表示 | 取上下文末位表示，添加模型内部输出头及 LoRA |
| 教师知识 | W32 量价特征、22 项确认结构、原生需求/供给与结构支持证据 | 逐日因果教师数据集、依赖范围与逐任务有效掩码 |
| 现有评分 | 外部 MLP A 为 34 维输入，B 为 44 维输入 | 保留为对照，不作为学生线上必需组件 |
| 资产校验 | 官方权重、tokenizer 和 vendor 源码均绑定冻结身份 | 新增学生 manifest、loader 分支和缓存身份，保留官方基线 |

上述源码路径相对于 `app/my_strategy/`；vendor 路径相对于 `app/`。截至本次工作区核查，原始库及合格来源末日为 **2026-10-16**，该日沪深 A 股合格来源 5,216 只，其中 5,190 只有至少 60 根历史。此检查未逐 bar 验证，也不代表这些股票均满足学生 256 根上下文要求。

## 2 第一版学习哪些知识

先学习稳定、密集的量价关系，再加入稀疏事件和结构。每个目标均保留可用性与质量，不能把未知填成“无事件”。

| 监督任务 | 教师来源和内容 | 学习方式 |
| --- | --- | --- |
| 连续量价关系 | W32 中相对成交量、成交额、缩量、量价背离代理、K 线实体与影线、区间位置、需求/供给强度 | 训练段标准化后的 Huber 回归；有界规则强度按连续目标处理 |
| 已知事件 | Spring、Test、SOS、LPS、Upthrust、SOW、LPSY | 多标签分类，按实际首次可见日监督；训练段内处理类别不平衡 |
| 确认结构 | 最近完成笔方向、收益、长度、量比、力度比、中枢相对位置、确认年龄 | 连续回归和类别分类；仅使用依赖历史完整可见的目标 |
| 真实未来 | 下一核验开盘至第 5 个核验交易日收盘的收益方向 | 内部三分类头，以真实成熟标签监督，并在独立时段校准 |
| 未来 K 线 | 真实后续 5 个交易日的 OHLCVA token | 保留 Kronos 双 token 自回归交叉熵 |

第一版只做日线、256 根上下文和未来 5 个交易日。周月结构、需要更早历史的中枢与持续事件先按依赖掩码处理，后续再验证 512 根上下文的必要性。W32 是本项目的威科夫量价实现，与 CZSC 笔/中枢结构分属不同知识来源，教师 manifest 分别记录身份。

规则需求/供给分数不是收益概率；Kronos 采样上涨占比也不是校准后的上涨概率。学生方向概率、规则强度和预测路径摘要分别输出。

## 3 教师数据如何构建

以 `(symbol, as_of)` 为样本原点，只输入当时可见的 OHLCVA，单位固定为价格原始口径、成交量股、成交额人民币元。沿用本项目 DB-first 和 `sh_sz_a_v1` 沪深 A 股范围，排除北交所；当前板块成员不得回填历史。

每个教师样本至少保存：`symbol`、`as_of`、`available_at`、`context_start`、`dependency_start`、`feature_schema`、`event_schema`、逐任务 `valid_mask`、质量原因、行情/日历/教师代码 SHA。学习未来的标签另存 `label_end` 和 `label_mature_at`。模型训练不读取账户库存、实际成交结果或未来筛选后的股票身份作为输入。

必须解决四个边界：

1. **按确认时间生成标签。** 形态锚点日期与首次可知日期分别保存。不能把后来确认的笔、中枢、Test、LPS 回填到早期位置；不使用未完成笔、未闭合周月或最终整张图重建出来的历史状态。
2. **教师与学生信息范围对齐。** 某个标签依赖早于学生窗口的笔、中枢或冻结边界时，不能宣称学生可以精确复现。优先保留原教师语义，并 mask 这些目标。无法证明依赖完整的任务，也先 mask。若改成窗口内重新初始化教师，必须建立新的教师 schema，不能冒充全历史 CZSC。
3. **失败留在审计人口。** 来源未知、单位异常、停牌、历史不足、公司行为疑似断点分别记录。无效输入可以排除训练，但要报告排除原因与比例；不可只保留教师成功或未来赚钱样本。
4. **覆盖日常调用人口。** 样本包含普通日、事件日和无事件日，不能只在 CZSC 买点出现日训练。按训练段确定事件采样权重，评估恢复自然频率；线上候选生成也必须能脱离 CZSC。

若以后用学习型概率教师或现有 MLP 产生软标签，必须使用按时间交叉拟合的预测或更早冻结模型。用完整数据训练出的教师回标同一训练期，不能视为独立教师证据。首版不依赖这个步骤。

## 4 学生结构和训练目标

冻结官方 tokenizer。复制 Kronos-base 作为学生，对 Transformer attention 的 `q_proj/v_proj` 增加 LoRA，首选 rank 8；原权重保持冻结，LoRA 必须参与主干前向和梯度更新。冻结 vendor 源码，通过外部适配器注入，训练与推理使用明确的新模型身份。

在末位隐层 `h_t` 上增加两类内部小头：量价/事件概念头、未来方向头。先短暂冻结主干训练小头，检查标签、量纲与梯度；随后训练 LoRA 和小头。**仅训练外挂分类头而不更新主干适配参数，只能算探针，不能算把知识蒸馏进 Kronos。**

联合目标建议为：

```text
L = L_AR
  + λ_pv    × L_连续量价
  + λ_event × L_已知事件
  + λ_struct× L_确认结构
  + λ_dir   × L_真实未来方向
  + λ_keep  × KL(冻结 Kronos-base 的 token 分布 || 学生 token 分布)
```

所有教师项分别按有效 mask 求均值，避免某一目标缺失或量纲大而主导梯度。冻结 base 只提供保持原生成能力的约束，不把其预测当真实未来。KL 在相同输入、相同 coarse token 条件上计算；不能让教师和学生各自随机采样不同 s1 后再直接比较 s2 分布。

`λ`、学习率、训练步数、早停规则及可训练参数清单在训练前登记，在调参段内选择；校准、政策和最终留出段不选这些参数。第一版不同时训练 tokenizer、不全量微调、不叠加强化学习。只有本轮实验证明瓶颈后，才建立新实验研究这些扩展。

生成能力与直接评分分开验收：信号模式用一次主干前向和内部方向头输出；需要预测图时再自回归采样。保留哪些概念头由输出需求决定，删除训练专用头后须重新验证生成结果。模型结构不压缩，因此本轮不承诺模型体积下降；速度收益来自减少在线教师计算及信号模式减少采样。

## 5 避免训练窗口泄漏

本地 tokenizer 的时间 attention 使用因果 mask，但当前预测归一化按整个输入 lookback 计算均值与标准差。训练必须以每个预测原点为单位复现这个输入契约：

1. 先截断到 `t`，用历史上下文计算 `μ_t/σ_t`，完成和推理一致的裁剪与数值处理。
2. 学生 context 独立编码，概念与方向监督只读末位 `h_t`；`h_t` 的计算不能看到未来。
3. 在独立 label-only 分支中，把已成熟后续行情用同一历史 `μ_t/σ_t` 变换。因 tokenizer 有历史上下文，可编码“context + 成熟 future”并只提取 future token 作为 target，但必须先通过前缀不变性检查，且不能把未来分支的 context 表示交回学生。
4. 自回归训练严格 shift；后续步只消费之前的真实 token。双 token 的 teacher forcing 只是解码训练机制，与 CZSC 教师含义不同。
5. 禁止用“历史 + 未来”的均值/标准差训练早期表示；禁止全数据统一标准化。窗口 token 缓存必须绑定原点、原始内容、归一化、tokenizer 和上下文身份，不能误用一份全历史 token 代替所有滚动窗口。

所有股票使用共同时间边界，顺序为 **训练 → 调参 → 校准 → 政策检查 → 最终留出**。边界按真实 `label_end` 清洗：跨过段末的未来标签不参与该段；同一原始事件衍生样本的跨段依赖也要清洗。教师 `available_at` 不得晚于样本决策时点，教师可见时间与未来标签 `label_mature_at` 还须不晚于各阶段实际数据截止时点。按至少 5 个交易日的目标跨度制定 purge；需要 embargo 的依赖另行登记。验证输入合法地包含较早历史，不应通过随机切分窗口制造独立样本的假象。训练段内部 batch 可以打乱，跨段时间关系必须固定。正式运行时，模型与校准包的生效时间不得晚于预测原点；历史重建另行标记，不回填成当时已生效的结果。

最终留出期还需检查是否曾被旧开发实验使用；被反复查看的历史不能再称为全新留出。官方预训练人口和末日未完全可核实，因此历史结果只作为回溯研究；真正前瞻从学生冻结并记录生效时间后开始积累。

## 6 分阶段工作和交付

以下为开发工作量估计；算力时间由资源试跑实测，不能直接用工作日估计替代训练 ETA。

| 阶段 | 具体工作 | 交付与完成条件 | 预计开发工作量 |
| --- | --- | --- | --- |
| P0 契约和资源试跑 | 冻结任务、频率、标签、切分、股票人口和预算；核查至少 256 根历史；10 股、约 1,000 个原点试跑 | 数据契约、内存峰值、每秒样本、梯度与保存/恢复证据 | 1 天 |
| P1 因果教师集 | 逐日提取连续量价、事件及可见结构；保存依赖和 mask；建立分片缓存 | 前缀重算/未来扰动一致；未知与无事件可区分；完整排除统计 | 2–3 天 |
| P2 学生训练 | 外部 LoRA、内部头、联合损失、固定 tokenizer、原子检查点和恢复 | 可训练权重确有变化；冻结资产不变；小样本可学习；恢复流程通过 | 2–3 天 |
| P3 对照实验 | 固定样本预算训练普通适配与蒸馏候选；校准、滚动测试及事件评估 | 证明增量来自教师监督，并报告不确定性、失败率和全部候选 | 2–3 天加实测算力时间 |
| P4 单模型接入 | 合并 LoRA；新资产清单、加载器、信号/路径两种输出；移除线上教师依赖 | 干净进程中禁止访问 CZSC/量价/外部 MLP 仍可完成输入到输出；合并前后等价 | 1–2 天 |
| P5 执行和前向验收 | 同人口同费用 Broker 回放、风险规则检查、显式启用影子观察 | 完整 Ledger、费用压力、回滚证据；资格按实际证据给出 | 1–2 天，前瞻观察另计 |

MVP 先使用预先冻结的 50–100 只分散沪深股票，按当时可见历史成交活跃度与波动分层，在可核验历史中固定抽取约 2 万–5 万个训练原点。涵盖上涨、下跌与震荡时期，并单留未参加训练的股票检查迁移能力；最终规模以 P0 覆盖检查为准。数据不足时缩小可证实范围，不补造历史。全市场扩展在 MVP 通过后单独登记。

本机核查为 Apple M3 Max、36 GiB 统一内存，项目 Python 3.12 环境的 MPS 可用，CUDA 不可用。可从 context=256、micro-batch=1、梯度累积和 float32 开始试跑，记录实际内存和吞吐；MPS 可用不代表这些算子、批大小或训练耗时已经验证。正式训练固定项目虚拟环境，避免混用系统 Python。若需要转 CUDA，仅做明确的数据/资产迁移与设备验证。

## 7 对照实验和验收条件

最少保留三个模型：A 为官方冻结 base；B 为同样本、同训练步数的普通 AR+方向监督 LoRA；C 为 B 加 CZSC/量价教师损失。B 和 C 使用相同内部方向头、未来标签、保持损失、可训练参数及预算，**C 对 B 才衡量教师知识的独立增量**。官方 base 没有训练后的方向头，其路径误差与采样方向摘要单独比较，不伪装成同一个校准分类器。

预算允许时再登记“仅连续量价”与“加事件/结构”的消融，并保留现有 CZSC+Kronos+MLP 系统作运营参考。最多 6 个候选、Kronos 配置最多 2 组；不开展 rank、窗口、损失权重的排列组合搜索。多个固定种子作为预登记重复实验，全部报告且计入算力预算，不能挑最好种子。

| 维度 | 验证内容 | 通过方式 |
| --- | --- | --- |
| 因果完整性 | 修改未来、截断重算、确认可见时间、窗口外依赖、归一化和标签成熟 | 所有契约检查通过；发现泄漏即停止结果排名 |
| 教师复现 | 连续目标 MAE/相关性，事件 PR-AUC、precision/recall、确认延迟 | 对训练先验/常量基线有增量，按任务和自然发生率报告，不能只报总体 accuracy |
| 未来方向 | LogLoss、Brier、可靠性与覆盖人口 | 校准及政策段按独立职责使用；通过现有先验门槛，并比较 C 相对 B 的增量 |
| 未来路径 | 归一化路径误差、token NLL、分位覆盖与宽度、OHLCVA 无效率 | 同原点、种子、采样预算；质量阈值固定，失败留分母，不事后修补路径 |
| 稳健性 | 至少 3 个滚动窗口、市场状态、活跃度及未见股票 | 报告配对日期块不确定性；不能只凭单股、单窗或单次收益晋升 |
| 真实执行 | 费用后收益、回撤、换手、敞口、完整周期、1/1.5/2 倍费用 | BrokerSimulator/Ledger 真实重放；沿用至少 5 股、3 窗、每策略 30 个完整周期等现有最低证据门槛，不足保持 pending |
| 部署独立性 | 禁止读取/调用教师与旧 MLP、冷热缓存、合并、加载和实际设备 | 独立新进程端到端成功，缓存不能掩盖依赖；数值误差容限在测试前冻结 |

P0 要预登记方向主指标、路径非劣界限、最大回撤/换手容限、事件任务最低支持数和延迟门槛。界限依据基线波动和业务容忍度确定，不能看完最终留出再写。C 只在教师复现上更好、但未来预测没有稳定增量时，保留为实验模型，不替代现任。

## 8 真正脱离在线 CZSC 的接入范围

不能只从预测函数删除 CZSC 调用，还让策略上游继续用 CZSC 找候选或提供止损位。P4 需检查候选生成、结构可用性门槛、评分、退出、风险位、缓存与界面解释的完整依赖。

学生模式在显式股票池中按固定日程推理，使用内部方向与事件估计产生候选；硬风险仅使用可直接核验的价格、ATR、账户库存、现金、T+1、涨跌停、流动性和费用等信息。若需要原生 CZSC 精确失效位，就不能声称这一策略已完全摆脱教师。学生预测的失效位不作为精确事实或唯一硬风险边界。

由于旧系统风险规则可能依赖 CZSC，执行比较分两层：先给 B/C 使用同一个、预先冻结的行情与账户风险规则，检验蒸馏本身；再把单学生完整系统与现有融合系统比较，并明确策略输入和风控变化。不能把更换止损产生的收益全部归因于蒸馏。

保留收盘决策、下一核验且可执行开盘成交、整手、T+1、费用、拒单、待退出和未平仓状态。数据或模型不可用时阻止新风险，已有库存的独立硬风险退出持续检查。模型负责估计，Broker/Ledger 负责实际成交。

## 9 模块和模型资产安排

建议新增的模块均位于 `app/my_strategy/`，正式实现时可按现有边界调整：

| 模块 | 职责 |
| --- | --- |
| `services/kronos_distill_dataset.py` | 预测原点、时间切分、输入/标签编码和分片读取 |
| `services/kronos_distill_teacher.py` | 冻结教师、依赖范围、确认时间、质量 mask 和缓存身份 |
| `services/kronos_distill_model.py` | 外部 LoRA 注入、学生 wrapper、内部头和合并 |
| `services/kronos_distill_training.py` | 联合损失、设备选择、预算、早停、原子检查点和恢复 |
| `services/kronos_distill_evaluation.py` | 消融、滚动预测、校准、部署等价及执行对照 |
| `scripts/train_kronos_distill.py` | 新的显式训练入口；与旧推理调参分开 |
| 现有资产/预测/任务/网页模块 | 学生 ID 选择、独立加载、结果身份、训练状态与资格 |

训练产物写入由 `core.paths` 解析的独立模型/实验根，通过 RunContext 保留谱系。检查点包括 LoRA/内部头、优化器/调度器状态、数据游标、随机状态、设备与源配置身份；取消为终态，续训通过显式新请求核验同一未完成实验，不能热改活跃任务。

交付模型包包含合并后的学生主干、保留的内部小头、config、tokenizer 引用及 SHA、归一化/校准参数和 manifest。manifest 至少记录官方 base SHA、教师/输入/标签 schema、代码 SHA、训练/调参/校准/政策/留出日期、模型冻结与生效时间、股票人口、随机种子、实际设备、训练预算、全部评价及资格。

新增学生 loader，保留官方资产固定 SHA 校验。缓存键绑定学生权重、内部头、tokenizer、输入、校准、采样配置和 schema；旧预测、旧账户不得改写成新模型结果。LoRA 合并前后分别核验主干 logits、内部头和固定种子路径。独立 KCPredict 若要使用学生，后续明确适配其模型包与输出协议，本轮不默认复制部署。

## 10 推进顺序与采用条件

先完成 P0/P1，把“教师在当时知道什么、学生能够看到什么、数据有多少”固定下来，再开发训练与做对照。MVP 核心判断是：**在相同数据、模型容量、未来标签和训练预算下，加入教师监督是否优于普通微调，并能在没有在线 CZSC 的干净环境中工作。**

验收通过后先新增可选择的学生候选，再显式启用影子观察。训练完成不自动取得纸上增仓资格，历史研究不自动取得独立前瞻认证；现有模型、账户和回滚引用保留。日常运行加载已冻结学生，不需要每日重训；后续遇到数据漂移或定期复评时，再离线运行教师、训练候选并重复验收。

本计划的收益目标是改善可验证的预测与执行表现；教师复现率本身不能证明盈利能力，研究结果不构成个股投资建议。
