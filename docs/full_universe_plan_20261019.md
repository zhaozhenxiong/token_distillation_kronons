# 全量股票蒸馏与分层样本验证计划

> 历史扩样计划。旧吞吐估算早于紧凑缓存和 240 股实测；最新执行结果见[240 股结果](results_240.md)，全量尚未执行。

日期：2026-10-19。状态：仅计划，后续执行待启动。本文件不启动数据集生成或训练。

建议顺序：只读分类盘点 → 数据加载与缓存改造 → 80股机制预检 → 240股正式消融 → 决定是否进入全量。

## 1. 已知事实与估算范围

- 实际行情表包含5,226只沪深A股、11,049,999行，存储日期为2015-01-05至2026-10-16；沪主板1,702只、深主板1,495只、创业板1,411只、科创板618只。
- 2026-10-16当天满足来源及交易价格标记的股票为5,216只，其中5,169只累计至少128条合格来源记录。这些计数不代表完整窗口核验通过，也不代表2023截面的可训练人口。
- 本机为M3 Max、36GiB内存。上一轮20股、四组、三个种子、每组512步的训练与独立评估总耗时45.66分钟。
- 本计划的时间估算沿用2024年至2026年的现有五段时间划分、128根上下文、5根标签、每5个交易日一个原点；不是对2015年以来全部历史逐日训练的估算。
- 5,226只是本地存储人口，不声称为历史全市场或无幸存者偏差人口。

目前只完成只读盘点；尚未统计完整2023特征、确认核心池、生成240/24名单或启动新训练。

## 2. 分层样本怎么选

主样本目标240只。选择信息截止2023-12-29，早于2024年训练起点；不得用2024年后的收益、覆盖、教师结果或模型分数决定名单。

| 维度 | 计划口径 |
| --- | --- |
| 板块 | 沪主板、深主板、创业板、科创板 |
| 流动性 | 各板块内2023有效日成交额中位数的低/中/高三档 |
| 波动 | 各板块内2023相邻有效交易日对数收益波动的低/中/高三档 |
| 主要分层 | 4×3×3，共最多36层；空层如实保留 |
| 分配 | 各板块优先保底20只，再按合格池规模分配；板块内兼顾九类覆盖 |
| 桶内抽样 | 固定策略版本、截止日、种子和股票代码计算SHA排序，确定性选择 |

核心池暂定要求：2023全年至少200根有效日线、截至切面最后128个独立日历会话完整、成交额中位数不低于1,000万元。该门槛用于定义主样本范围，不代表低于门槛的股票没有研究价值。若合格池或某层不足，按预先冻结的规则重新分配并记录，不按模型表现补股。

有效日线须满足冻结来源白名单、`has_trade_price=1`、合法有限OHLCVA、正成交量额和已验证日历。波动只使用相邻会话，排除已标记可疑断点的收益对，并保留原始波动作敏感性描述；不将可疑断点直接解释为已确认公司行动。现有行业元数据若缺少2023时点证据，不用于历史分层。

源表没有`available_at`；上述切面首先指交易日期截止，历史摄取及修订时点仍未核验。若继续使用收盘时刻重建可用性，必须保留这一假设，不能把日期截断当作真实历史可得性的证明。

另设24只压力样本，同样仅使用截至2023-12-29的信息，计划覆盖低流动性、缺口/零量、历史不足、可疑价格断点四类，每类目标6只；不足时披露，重叠按固定优先级去重。压力样本检验拒绝、mask和适用边界，不强行补造历史，不与240只主样本混算总体有效性。

每层保存候选数、样本数、抽样概率与哈希排名。后期缺口只影响窗口准入，不更换已选股票。首条存储日期称为“首次观测日期”，不冒充上市日期。最新新增股票在全量阶段按其当时可用历史单列队列，不补入2023截面。

验收：任意改变2024年后的价格、覆盖及收益，主样本和压力样本名单、2023特征和配额都不变。

## 3. 全量前必须解决的数据工程问题

现有实现会整份加载全部分片；编排父进程保留数据，训练/评估子进程又各自加载。按当前记录格式外推，5,226股最多约67.4万个窗口，JSON约61.5GiB，父子两份Python对象约392GiB，超过36GiB物理内存。

计划改造：

1. 按股票/时间分片，流式构建、验证和加载，避免父进程持有完整样本。
2. 原始行情、来源证据与窗口索引分离，减少重叠128根上下文的重复存储；保持逐窗口可追溯。
3. 建立冻结token缓存，按样本、归一化、tokenizer及配置SHA绑定；四组、各种子复用，保留前缀不变性核验。
4. 训练统计只在train段拟合；通过固定索引维持各组相同样本顺序，改变分片大小不得改变人口和时间边界。
5. 小规模测峰值内存、磁盘、教师生成、编码、优化和评估耗时。单进程和编排合计目标峰值不超过24GiB；超过时先调整加载，不进入全量。

所有代码、缓存和派生文件只写本工程。源库经冻结adapter只读连接，官方权重/tokenizer与ICT vendor保持只读，不复制大权重。

## 4. 先验证蒸馏机制，再扩大算力投入

上一轮连续事实重建已有改善，但事件BCE仍弱于频率常数，教师带来的方向增益很小。直接增加股票数不能替代以下验证。

- 给内部方向/教师头提供预测原点可得的归一化统计，补目前百分比目标可能缺少的输入信息；各对照组采用相同架构与输入，不修改官方tokenizer/vendor。
- 检查事件任务的正例数、训练频率基线及共享LoRA梯度；权重或损失变动仅在train/tune上确定，另冻结新协议，避免同时无边界搜索多项参数。
- 从240主样本中固定抽取80股做机制预检，加入“冻结主干仅训练内部头”和“打乱train教师标签”的控制；不使用其他阶段标签，也不以结果换股。
- 保留同目标重复运行，用于测量MPS数值波动，避免把极小差异直接解释为教师语义贡献。

机制预检的额外控制不计入下表四组、三个种子的耗时。若连续重建、事件或预测目标仍无足够信号，先定位原因，不自动进入全量。

## 5. 240股正式实验协议

沿用无教师、CZSC、ICT、双教师四组，三个固定种子42/123/2026。所有组使用相同人口、初始化、LoRA容量、样本顺序、优化器与共同方向选点标准；教师预算及所有改动在运行前冻结。

训练预算按两遍有效训练窗口计算，`max_steps=ceil(2×N_train/4)`，不沿用全局1,024窗口上限，也不把固定512步称为全量学习。总共评估5次tune：初始化一次，加四次训练进度检查，间隔随总步数扩大；最终一步仍须评估。

五段时间顺序不变，跨界或未成熟真实标签清洗。原生教师事实和学生估计分别标记。未来标签断点筛选如继续使用，只能称事后标签质量准入，并披露其条件人口，不能用作预测时过滤规则。

评估分别回答：

1. 连续教师重建是否优于train均值和中位数；事件BCE是否优于train频率常数。
2. 方向LogLoss/Brier是否优于同种子无教师与训练先验，准确率和各类别误差如何变化。
3. 条件token NLL是否进一步优于无教师；该指标与自由生成价格预测分开，未实现的后者不得报告成功。
4. 双教师是否优于单教师，差异是否超过种子与数值波动；按共同预测日期块配对估计区间。

增加股票数不会增加原有24个留出日期的独立时间证据。沿用已查看的时间段仍为回溯研究；跨时期稳定性须用额外独立时间窗口或后续新数据验证，不能把旧留出重新称为未见测试。

## 6. 预计需要多久

按独立日历、标签跨界清洗后，每股至多有train/tune/calibration/policy/holdout各71/16/7/11/24个窗口；实际质量核验后会减少。

| 规模 | 总窗口上限 | 两遍训练步数/组 | 单次双教师训练及四阶段评估 | 四组×三个种子 |
| --- | ---: | ---: | ---: | ---: |
| 240股 | 30,960 | 8,520 | 中心约52分钟；规划26–104分钟 | 中心约10.4小时；规划5–21小时 |
| 本地5,226股 | 674,154 | 185,523 | 中心约18.8小时；规划9–38小时 | 中心约9.4天；规划5–19天 |

这些是依据当前实际45.66分钟实验的合并吞吐作容量外推，范围为中心值的0.5–2倍，不是置信区间或完工承诺。训练、编码和tune没有完整独立计时，分解仍有不确定性。前提是先解决内存，并保持共5次tune；不包含数据工程开发、教师数据生成、额外机制控制、冷却/休眠或失败重跑。token缓存带来的实际加速需要重测，不预先计为确定收益。

可复算的容量模型为：单组秒数约等于`3 + 0.0246×(N_train+N_tune) + 0.104×steps + 5×0.0414×N_tune + 0.0660×N_nontrain`，其中`N_nontrain`包含四个非训练阶段，tune会在独立重载评估时再次计入；四组、三个种子的总量再乘12。0.0246秒/窗口为预处理合并代理，0.0660秒/窗口为独立评估合并代理；0.0414秒/窗口与0.104秒/优化步是用合并耗时推定的拆分假设，不能独立识别为纯前向或纯优化实测。该公式回代原有1,024/311/1,133窗口和512步，可得到12组约45.65分钟，近似原记录45.66分钟；代入240股和5,226股的日历窗口上限，分别得到单组约52分钟和18.8小时。

两个预算陷阱：

- 全量仍跑512步，每组只呈现2,048个训练窗口，约为训练窗口上限的0.55%，不能据此验证全量有效性。
- 全量两遍训练若照搬每128步全量tune，会产生约1,451次tune，评估成本膨胀到数百天级；必须显式更改检查频率。

教师生成时间尚无可靠全量基准。先在80股和240股分别记录每类教师的窗口吞吐、冷启动和I/O，再给出包含生成的总工期；不把上述训练评估预算冒充完整端到端预算。
